# Hetionet v1.0.0 実データ：100,000 TripleのGNN／BFS／融合比較

実施日：2026-11-14  
入力：ユーザー提供 `hetionet-v1.0.0.zip` の公式 `hetionet-v1.0-nodes.tsv` と `hetionet-v1.0-edges.sif.gz`。

## 0. まとめ

- 元の **47,031ノード／2,250,197エッジ** から **2,330ノード／100,000 Triple／24関係** を抽出した。
- **25 epochs × 5 seeds（42–46）× 2特徴モード** のJAX GraphSAGE学習・評価を実測した。
- ノード名＋種類の場合、5 seed平均MRR@10は **GNN 0.1240 / BFS 0.1077 / 融合 0.1353**。
- ノード種類のみの場合、平均MRR@10は **GNN 0.0794 / BFS 0.1077 / 融合 0.1291**。
- 融合はBFSに対して両特徴条件の**各5 seedで上回った**。ただし同じ抽出グラフ上でseedを変えた結果であり、有意差や一般化を示すものではない。
- **1万Tripleよりスコアの絶対値が低下**したが、候補ノード数・関係分布・抽出グラフ・評価用クエリが異なるため、データ追加の効果を直接測る学習曲線ではない。

**特徴量の扱い（主解析）**：元のHetionetに含まれる実ノード名は、推論時に利用できる正当な情報です。人工合成グラフの `clan` と混同しないでください。本実験の主結果はノード名＋種類の `kind_name` であり、`kind_only` は寄与を切り分けるための補助アブレーションにすぎません。BFSは名称情報を用いないので、3手法の比較は同じ候補・正解を使うシステム比較であり、すべての特徴量を統一したアルゴリズム比較とは区別します。

## 1. データの構成

| 項目 | 1万Tripleの前回実験 | 今回10万Triple |
|---|---:|---:|
| 母集団 | Hetionet Full | 同じ原本 |
| サンプルTriple | 10,000 | **100,000** |
| サンプルノード | 495 | **2,330** |
| 関係型 | 24 | 24 |
| ノード特徴 | type + 実ノード名／typeのみ | 同じ |
| epoch | 25 | 25 |
| 1 epochの正例監督上限 | 4,096 | 4,096 |
| 検証・テストクエリ上限 | 各128 | 各128 |
| embedding dimension | 16 | 16 |
| Split seed | 42–46 | 42–46 |

抽出はv6の **ノード型層別multi-start frontier → 誘導エッジ → ランダム全域森＋uniform fill**。目標1万／10万の両方を実際のHetionetから抽出した。ノード名に人工的な`clan`やクラスターラベルは付加していない。

- 10万Tripleサンプルに含まれる前回のTripleは **8,045 / 10,000**。前回の495ノードは全て今回のノード集合に含まれるが、Triple集合は完全な入れ子ではない。
- Train/Validation/Test（seed42）：**72,638 / 13,681 / 13,681**。seed45だけTrain 72,637 / Validation 13,682 / Test 13,681。
- 10万Tripleの最多関係は `AeG` 39,617件（39.6%）、`GpBP` 13,962件（14.0%）、`Gr>G` 12,601件（12.6%）。上位3関係の合計は約66.2%。
- Testの型付き候補集合の中央値はseedによって **871.5〜1,179.5**。前回の10k・seed42の218から大幅に増大し、同じMRR絶対値を要求するのは不適切。

## 2. 学習・評価方法

- v6の **GraphSAGE型JAXエンコーダー＋関係ベクトル付きコサインクエリ**。16次元埋め込み、Adam、25 epoch。ランキング損失はpositive Triple対同型負例4件のsampled softmax。
- 1 epochあたり最大4,096の正例Tripleをランキング損失に使用する。**全学習エッジはメッセージパッシングに使用**するが、全Tripleが全epochで直接positive損失に登場するわけではない。この上限は10万Tripleにとって学習不足の一因になり得る。
- 同じ無向ノードペアに属する複数Tripleを分割横断させず、Trainの実エッジだけをBFS・GNNの隣接情報に使用。
- 評価タスクは `(head, relation) → tail`。全3手法は**同じrelation-compatible候補集合と同じ正解集合**を使用。Validationで融合係数を選び、Testは固定で評価。
- GNN単独は厳密な全候補スコア順。BFSは学習グラフの最短距離→次数→IDによる順位。融合はGNN/BFSの順位パーセンタイルの重み付き和。**Voyager近似ANNは本比較に使用していない**。
- 評価はTestの全Tripleではなく、関係別に決定論的に選んだ**最大128 `(head,relation)` クエリ**。数値はクエリmacro平均。

## 3. ノード名＋ノード型（kind_name）：5 seed平均±標本標準偏差

| 手法 | Hits@1 | Hits@10 | Recall@10 | MRR@10 |
|---|---:|---:|---:|---:|
| GNNのみ | 0.0625 ± 0.0110 | **0.3141 ± 0.0443** | 0.2115 ± 0.0188 | 0.1240 ± 0.0173 |
| BFSのみ | 0.0500 ± 0.0070 | 0.2813 ± 0.0485 | 0.2280 ± 0.0393 | 0.1077 ± 0.0046 |
| **BFS＋GNN** | **0.0719 ± 0.0202** | 0.3125 ± 0.0282 | **0.2315 ± 0.0278** | **0.1353 ± 0.0158** |

**各seedのTest MRR@10**

| seed | GNN | BFS | BFS+GNN | α（GNN側重み） |
|---:|---:|---:|---:|---:|
| 42 | 0.14975 | 0.10947 | **0.15546** | 0.85 |
| 43 | **0.13061** | 0.10547 | 0.11388 | 0.80 |
| 44 | 0.11114 | 0.10067 | **0.12941** | 0.55 |
| 45 | 0.10613 | 0.11179 | **0.13321** | 0.90 |
| 46 | 0.12230 | 0.11117 | **0.14478** | 0.20 |

- 平均差は **GNN−BFS = +0.0163**（GNNが4/5 seedで上回る）。
- 平均差は **融合−BFS = +0.0276**（融合が5/5 seedで上回る）。
- 平均差は **融合−GNN = +0.0114**（融合が4/5 seedで上回る）。
- 選択αがseed 46で0.20まで下がるなど、相補性はsplit依存。

## 4. ノード名称を除いた対照（kind_only）：5 seed平均±標本標準偏差

| 手法 | Hits@1 | Hits@10 | Recall@10 | MRR@10 |
|---|---:|---:|---:|---:|
| GNNのみ | 0.0219 ± 0.0102 | 0.2609 ± 0.0404 | 0.1769 ± 0.0193 | 0.0794 ± 0.0150 |
| BFSのみ | 0.0500 ± 0.0070 | 0.2813 ± 0.0485 | 0.2280 ± 0.0393 | 0.1077 ± 0.0046 |
| **BFS＋GNN** | **0.0688 ± 0.0128** | **0.3094 ± 0.0315** | **0.2446 ± 0.0266** | **0.1291 ± 0.0165** |

- GNNのみはBFSに全5 seedで及ばない。**名称情報からの寄与は大きい**。
- 融合はBFSを全5 seedで上回るが、その差は**平均+0.0214**。GNN単独の改善とは区別する。
- BFSはノード名を参照しないため、両特徴条件で同一の値となる。

## 5. 前回1万Tripleとの比較上の注意

| 特徴：kind_name | 前回1万Triple MRR@10 | 今回10万Triple MRR@10 |
|---|---:|---:|
| GNN | 0.2750 | 0.1240 |
| BFS | 0.2148 | 0.1077 |
| BFS+GNN | 0.2654 | 0.1353 |

これを**「データを増やすと学習が悪化する」**と読んではならない。ノード数、候補集合、関係頻度、抽出部分グラフ、holdout正解、評価クエリが変化しており、同一タスクでのLearning Curveではない。

本当にスケーリングを確認するには、**固定したグラフ・候補集合・Validation/Test**上で、Trainの監督Triple数だけを増やした比較が必要。加えて、10万規模での `max_positives_per_epoch=4096` を増減させるアブレーションも必要。

## 6. 検証／実行環境

- 正式なZIP内TSV／SIF.gzと、以前展開した原本のSHA-256が一致することを確認。
- 10万Triple/2,330ノード抽出に成功、重複Tripleなし。
- 10回の25 epoch JAX学習と各128 Testクエリの厳密検索を完走。
- 5 seedすべてのTrain/Validation/Testで、無向ノードペア集合の交差が空。計算済みメトリクスはクエリ別CSVから再計算して一致。
- 評価高速化のため、キャッシュ済み学習エッジ・BFS距離・NumPy `lexsort` を使用。**旧v6の1万Tripleの全5 seedで、全指標と融合係数が一致**することを確認。
- `Polars` のCSV入口のみ、実験実行環境では `pandas` で代替。JAXの学習、パラメータ、スコア式、評価条件はv6を維持。
- Voyager/HNSW、Ollama/LLM、Mac Docker上での統合起動、医学的妥当性は本実験の検証対象外。

## 7. 再現方法／ファイル

- `data/hetionet_demo/`：実データ由来の10万Triple CSVとメタデータ。
- `src/gnn_rag/fast_evaluation.py`：旧結果との一致を検証した高速化評価ロジック。
- `scripts/run_100k_real.py`：JAX学習・3手法比較。`pandas`を利用する実行環境向けCSVアダプター。
- `results/kind_name/`、`results/kind_only/`：各seed JSON、クエリ別CSV、学習済みノード埋め込み・関係ベクトル。
- `results/aggregate_5seed.json`：全5seed集計とseed別差分。
- `scripts/validate_100k_results.py`：分割・候補集合・集計・学習済みベクトルの整合性チェック。
- `compose.yaml`：Polarsを使った通常のDocker Compose学習／RAG実行にも対応。`HETIONET_TARGET_TRIPLES=100000`をデフォルトに設定。

```bash
# ZIPを展開したプロジェクトルートにて（JAX, NumPy, pandas が必要）
PYTHONPATH=src python scripts/run_100k_real.py \
  --input data/hetionet_demo --output results/kind_name \
  --seed 42 --epochs 25 --eval-max-queries 128 \
  --train-max-positives 4096 --feature-mode kind_name

PYTHONPATH=src:scripts python scripts/validate_100k_results.py
python scripts/aggregate_100k_results.py --results results
```

数値はHetionet由来の**実測値**。ただしこれは局所的なTransductiveリンク検索の検証であり、臨床的真実やLLMの回答品質の証明ではない。
