# Hetionet v1.0.0 実データによるGNN/BFS比較評価（10,000 Triple）

実施日: 2026-11-14 | 添付Hetionet ZIPを実際に展開・抽出し、v6のJAX学習とランキング評価を実行。

## 1. データと方法

- 原本：**47,031ノード / 2,250,197エッジ**（添付zip内のTSV＋SIF.gz）。
- サンプル：**495ノード / 10,000 Triple**、24関係型。抽出seed=42。
- 母集団の全エッジで候補を抽出する**誘導部分グラフ**方式。ランダムIIDサンプルではない。
- Train / Validation / Test：**7,414 / 1,293 / 1,293 Triple**（seed 42時。ほかのseedも同数）。同じ無向ノードペアを分割横断させない。
- v6のGraphSAGE型JAXエンコーダー＋関係クエリ。埋め込み16次元、25 epoch、各epoch正例最大4,096、正例あたり同一ターゲット型の負例4個。
- 比較：GNN単独＝**全候補厳密ランキング**／BFS＝Trainグラフの最短距離順位／融合＝ValidationのMRR@10で学習した順位パーセンタイルの混合。
- 同じ関係型に対応する候補、同じTest正解、同じ上限128クエリ／分割。評価クエリは関係別に決定論的抽出。
- 5 seed（42,43,44,45,46）で**同一の抽出部分グラフ**を使い、分割・初期値・学習を変更。seed間の結果は統計的に独立な集団サンプルではない。

## 2. 主結果：自然ノード名＋ノード型の特徴（kind_name）

| 方法 | Hits@1 | Hits@10 | Recall@10 | MRR@10 |
|---|---:|---:|---:|---:|
| GNN単独 | 0.1641 ± 0.0146 | 0.5672 ± 0.0285 | 0.4659 ± 0.0259 | 0.2750 ± 0.0181 |
| BFS単独 | 0.1234 ± 0.0187 | 0.4375 ± 0.0371 | 0.4058 ± 0.0277 | 0.2148 ± 0.0227 |
| BFS＋GNN | 0.1625 ± 0.0187 | 0.5281 ± 0.0532 | 0.4547 ± 0.0409 | 0.2654 ± 0.0283 |

値は5 seed平均 ± 標本標準偏差。MRR@10の平均差（GNN−BFS）は **+0.0602**。

## 3. ノード名情報を除外した対照（kind_only）

| 方法 | Hits@1 | Hits@10 | Recall@10 | MRR@10 |
|---|---:|---:|---:|---:|
| GNN単独 | 0.0813 ± 0.0320 | 0.5156 ± 0.0395 | 0.4194 ± 0.0288 | 0.1929 ± 0.0245 |
| BFS単独 | 0.1234 ± 0.0187 | 0.4375 ± 0.0371 | 0.4058 ± 0.0277 | 0.2148 ± 0.0227 |
| BFS＋GNN | 0.1359 ± 0.0334 | 0.5031 ± 0.0408 | 0.4426 ± 0.0432 | 0.2349 ± 0.0328 |

ノード型だけにするとGNN単独のMRR@10は低下し、BFS単独を平均では下回る。**GNN優位はグラフ構造だけの効果ではなく、実在するノード名の語彙情報にも依存**する。
これは以前の合成`clan`ラベルとは異なり、元Hetionetの名称を用いた正当な特徴量。ただし、BFSが名称情報を使わない点では入力情報量に差がある。

## 4. サンプル構造と注意点

### 関係型の偏り

| 関係 | Triple数 | 全体割合 |
|---|---:|---:|
| `AeG` | 5,595 | 56.0% |
| `AdG` | 1,129 | 11.3% |
| `AuG` | 1,103 | 11.0% |
| `GpBP` | 554 | 5.5% |
| `Gr>G` | 547 | 5.5% |
| `GiG` | 288 | 2.9% |
| `CcSE` | 152 | 1.5% |
| `GpCC` | 83 | 0.8% |

上位3関係で78.27%のTripleを占める。
サンプラーが密集した局所部分グラフを選んだため、5,000ノード上限でも**実際に選ばれたのは495ノード**。データ規模の効果を結論するには、同じ評価集合のまま学習Triple数を増やした学習曲線と、異なるサンプラーでの追試が必要。

### 評価の限界

- 本データの抽出はTrain/Test分割より**前**に全エッジを使っている。モデルに保留エッジを渡してはいないが、抽出母集団と評価対象の選択には構造バイアスがある。
- 一部クエリは候補数が小さい（seed42は最小2、中央値218、最大270）。容易な関係が混在している。
- `same-type`の未観測Tripleを負例とみなすため、未知の真正関係が負例に混ざり得る。
- 「GNN単独」はVoyager/HNSWではなく厳密全候補検索。**Voyagerの近似精度・検索速度は未測定**。
- Ollama、LLM回答生成、医療的妥当性は評価していない。
- CSVの読み込み境界は、実行環境でPolarsが利用できなかったためpandasで互換化。**v6のJAX学習・分割・スコア関数・評価モジュールは変更していない**。
- 単一の誘導部分グラフ上の5 seedなので、独立サンプルに基づく有意差を主張しない。

## 5. 結論

1. 現在の1万Tripleサンプルに対して、実在する名称情報を含めたGNN単独は**5 seedすべてでBFSのMRR@10を上回った**。
2. BFS＋GNNはBFSを5 seedすべてで上回るが、GNN単独を常に上回るわけではない。
3. ノード名を除いたときの低下が大きいため、単純に「学習量を増やしたからGNNがBFSを超えた」とは言えない。
4. 次は固定Test集合のLearning Curve（1k, 3k, 10k, 30kなど）と、幅広いノードを選ぶサンプラーを比較する。

## 6. 再現と出力

- 元データ：ユーザー添付 `hetionet-v1.0.0.zip`（原本は配布ZIPに同梱しない）。
- `data/hetionet_demo/`：v6サンプラーで作成したノードCSV・Triple CSV・メタデータ。
- `scripts/run_10k_real.py`：pandas経由のCSV読込のみ置換し、v6本体で学習・評価した実行スクリプト。
- `results/kind_name/`：5 seedの評価JSON、Markdown、クエリ別CSV、学習済み埋め込み。
- `results/kind_only/`：同様の対照実験。
- `results/kind_name/aggregate_5seed.json`：集計結果の機械可読JSON。

ローカル例（JAX / NumPy / pandas が必要）：

```bash
PYTHONPATH=src python scripts/run_10k_real.py --input data/hetionet_demo --output results/kind_name --epochs 25 --seed 42 --eval-max-queries 128 --train-max-positives 4096
```

v6の通常のDocker Compose経路ではPolars／Voyagerを引き続き使用します。ただし同じ評価値を保証するものではなく、入力Tripleの順序と環境を固定して検証してください。
