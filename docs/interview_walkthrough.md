# 二次面接向け：5分で説明する順序

## 0:00〜0:45 — 問題設定

> 知識グラフから、質問に関連する概念を抽出してLLMへの追加コンテキストとして使う構成です。単純にKGの隣接エッジを辿るだけでなく、ノード周辺の文脈をGNNの潜在表現として圧縮し、ANNによって検索候補を得ることを狙いました。

注意：**従来の検索より有効だった、とデモだけで断定しない**。実際の有用性はベースラインとの比較が必要。

## 0:45〜1:45 — データとモデル

- `data.py`: Polarsで読み込んでスキーマ・ID・重複を検証。モデル境界はNumPy/JAX。
- `split.py`: 元の正例を分割し、val/testエッジをtrainの近傍集約に与えず、相互（逆向き）エッジを同じ分割にする。
- `model.py`: 自ノード表現と隣接ノードの**重み付き平均**を連結し、2層の学習可能な線形変換 + ReLUに通す。更新式は下記。

\[
 m_v^{(l)}=\frac{\sum_{u\in N(v)} w_{uv}h_u^{(l)}}{\max(\varepsilon,\sum_{u\in N(v)}w_{uv})},\qquad
 h_v^{(l+1)}=\sigma\!\bigl(W_l[h_v^{(l)}\Vert m_v^{(l)}]+b_l\bigr).
\]

実装は近傍集約で逆方向を追加し、教師信号のエッジ方向は保持します。最後の層は線形変換後にL2正規化します。

\[
 s(u,v)=\exp(\alpha)\,z_u^\top z_v,\qquad
 \mathcal L=\operatorname{BCEWithLogits}(s,y).
\]

**ただしデコーダは内積なので、教師エッジの向きを表す能力は限定的**です。方向性が本質的なら非対称デコーダ（bilinear / MLP）に変更します。

## 1:45〜2:45 — 学習と検索

- `train.py`: JAXの自動微分とCPUでも動く更新、固定seed。validation/testのAUCは例示にとどめる。
- `retrieval.py`: 学習済み埋め込みをVoyager（HNSW）に渡す。元IDとインデックスIDを別管理。
- `multi_hop`: `hops`, `top_k`, `beam_width`で探索数を制御。学習ではなく**近傍探索による候補系列化**。

## 2:45〜3:30 — LLMとの境界

- `context.py`: 各候補系列のノードラベル・説明を外部コンテキストに構築。今回LLMは呼び出さない。
- 入力データを信頼できる命令と区別する、機密データを外部LLMに送らない前提を要件で決める。**RAGだから自動的に機密性が守られるわけではない**。

## 3:30〜5:00 — 技術的なトレードオフ

- **旧版の問題:** `net_fn(graph).nodes` と学習済みパラメータの接続、分割境界、ID、`top_k ** hops` のメモリコスト。
- **今回の修正:** 推論時の学習済みパラメータ、テスト・ID対応、探索幅制限。
- **未解決:** graph-constrained pathか、ANN類似チェーンか、評価データの作成、RAGの真の品質の定量化。

## 想定される質問と返答のポイント

**Q1. JAXでやる必要がありますか？**

行列演算・勾配・JITを明確に扱え、パラメータを関数引数で保持する設計がレビューしやすいという選択です。小規模で必須ではありません。

**Q2. GraphSAGEで何を学習していますか？**

観測されたリンクと負例を識別するような潜在表現です。必ずしも「正しい意味関係」全体を学習したわけではありません。

**Q3. 近傍検索結果はグラフ上の正しいpathですか？**

いいえ。類似度の連鎖であって、実際のエッジが存在する保証はありません。トレーサビリティが必要ならKGのエッジで候補をフィルタする別モードを実装します。

**Q4. なぜHNSWで、FAISSなどではないのですか？**

実装時にVoyagerの軽量なインターフェースを活用しました。用途によって近似精度/検索時間/メモリを比較し、選び直すべきです。

**Q5. 性能は何で示しますか？**

Link PredictionのAUCだけでなく、検索Recall@k/MRR、回答の根拠充足率・Hallucination率・レイテンシ・費用をベースラインと比較します。

**Q6. 大規模KGならどうしますか？**

今回の候補列列挙はbeam searchで制限しましたが、エッジのバッチ処理、サンプリング、埋め込みの増分更新、ANN再構築頻度が課題です。

**Q7. なぜGATを使わないのですか？**

元コードにはGAT案もありましたが、この版では近傍平均の挙動を説明可能に保ちました。必要なら重要度の異なる隣接ノードの注意機構を比較する仮説を立てます。
