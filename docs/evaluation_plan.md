# より広範な評価計画（現時点では一部未実施）

## 目的別の指標を分離する

| 目的 | 指標 | 比較対象 |
|---|---|---|
| GNNによる構造学習 | Edge ROC-AUC / AP（正負例方針を明示） | 特徴量のみのMLP、ランダム埋め込み |
| ANNでの候補再現 | Recall@k、正確な全件探索とのtop-k一致率 | brute-force Euclidean |
| 質問に対する検索品質 | MRR、nDCG、Recall@k | BM25、テキスト埋め込みRAG、KG隣接探索 |
| 最終回答 | 根拠適合率・事実性・未回答率・専門家評価 | 同一LLM・同一prompt予算のbaseline |
| システム | p50/p95レイテンシ・メモリ・再学習費用 | シンプルなBM25/Vector RAG |

## リークを避けるための分割

1. 業務領域、施設、文書生成日付など、実際の利用時に発生する分布差を考慮してtrain/testを分ける。
2. KGに重複/反転リンクがあるなら、分割単位をエッジでなく関係ペアや時点に切り替える。
3. 予測対象リンクをメッセージパッシングの入力から除去。
4. 「KGに未記載＝誤り」とは限らない。負例を未観測エッジから作る場合のバイアスを報告。
5. seed 3〜5以上、分散、95% CI、比較時に条件を一致させる。

## 小さな反証可能仮説

同一の質問セット、同一コンテキストtoken数で、**GraphSAGE埋め込み＋Voyager**が**raw node features＋Voyager**よりRecall@kを改善するかを測る。改善しなければ、追加のGNN学習は要らない可能性がある。

## プロダクト・運用上の検討事項

- 実データ・個人情報の取扱い: 保存、アクセス制御、LLM送信先、監査ログ、患者単位の安全な分離。
- Prompt Injection / data poisoning: 外部知識を命令として実行せず、生成物を検証する。
- データの更新と埋め込みの同期: ノードID安定性・インデックスのバージョニング・ロールバック。
- APIの認証・監査・メトリクス・スロットリングはデモでは省略。
